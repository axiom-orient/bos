# Product Guide

## Overview

`bos` is an operations CLI for iOS project bootstrap and release workflows.

Its public surface is intentionally narrow:

- `doctor`
- `plan`
- `apply`
- `verify`
- `app-register`
- `release-init`
- `release-check`
- `release-run`

The product contract is simple:

- planning input becomes `.bos/plan/blueprint.yaml`
- blueprint plus profile become a generated project
- release commands read profile plus signing environment

## Runtime Contract

### Required Inputs

- planning documents under `PLAN/`, or one PRD passed with `--prd`
- onboarding SSOT at `.bos/config/profile.yaml`
- signing secrets at `.bos/config/signing.env`

### Generated Inputs

- `.bos/plan/blueprint.yaml` is the only default blueprint path

How it appears:

- `profile.yaml` is auto-created when a profile-using command first resolves the default path
- `signing.env` is auto-created for release-scoped commands
- `blueprint.yaml` is generated by `bos plan`, or passed explicitly with `--blueprint`

### Metadata Precedence

`CLI override > profile.yaml > blueprint/PRD marker > deterministic default`

### Canonical SSOT Fields

`.bos/config/profile.yaml`

- `identity.companyName`
- `identity.appName`
- `identity.appIdentifier`
- `identity.appleTeamId`
- `release.primaryLanguage`
- `release.sku`
- `release.matchGitURL`

`.bos/config/signing.env`

- `ASC_ISSUER_ID`
- `ASC_KEY_ID`
- `ASC_KEY_P8_BASE64`
- `MATCH_PASSWORD`

## Command Contract

| Command | Purpose | Required input | Main writes |
|---|---|---|---|
| `doctor` | validate local toolchain and signing prerequisites | optional scope-specific profile/env | `.bos/artifacts/doctor/`, `config/toolchain.lock.yaml` |
| `plan` | generate `.bos/plan/blueprint.yaml` | `PLAN/` or `--prd` | `.bos/plan/blueprint.yaml` |
| `apply` | generate or reconcile Tuist/TMA scaffold | blueprint, profile | generated project files, `.bos/state/bos.state.yaml`, `.bos/artifacts/apply/` |
| `verify` | run smoke validation for generated projects | generated project, full Xcode developer dir | `.bos/state/bos.state.yaml`, `.bos/artifacts/verify/` |
| `app-register` | create or confirm Bundle ID and ASC app record | profile identity fields, ASC env, optional blueprint | `.bos/artifacts/app-register/`, synced profile output |
| `release-init` | create fastlane scaffold | blueprint, profile, signing env | `fastlane/Fastfile`, `fastlane/Appfile`, `fastlane/Matchfile`, `.bos/artifacts/release-init/` |
| `release-check` | validate live release readiness | profile, signing env, release scaffold for cert modes | `.bos/artifacts/release-check/`, `.bos/state/bos.state.yaml` |
| `release-run` | build, upload, or submit signed artifacts | blueprint, profile, signing env, release scaffold, buildable project | `.bos/artifacts/release-run/`, IPA, `.bos/state/bos.state.yaml` |

## Behavioral Rules

- `verify` suppresses debug signing for the smoke path.
- `app-register` is idempotent. Existing resources return `existing`, not failure.
- `release-init` is local scaffold generation only.
- `release-check` is the live release-readiness gate.
- `release-run` owns the signed `build | beta | release | submit` stages.
- `readonly-certs` is the default readiness path.
- `sync-certs --allow-write` is only for the first signing seed on an empty setup.
- `MATCH_GIT_URL` belongs in `profile.yaml`, though a shell environment override may still provide the effective value.

## Standard Flows

### Flow A. New Project

```bash
bos doctor
bos plan --plan-dir ./PLAN
bos apply --mode init
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer bos verify
```

### Flow B. App Store Connect Onboarding

```bash
bos doctor --for app-register
bos app-register
```

### Flow C. Release Preparation

```bash
bos doctor --for release-init
bos release-init
bos doctor --for release-check
bos release-check --mode readonly-certs
```

### Flow D. Signed Distribution

```bash
bos doctor --for release-run
bos release-run --stage build
bos release-run --stage beta
```

## Constraints

- `primaryLanguage` currently supports `en-US` and `ko-KR`
- full `verify` depends on a real Xcode developer directory
- release operations depend on live Apple and Git systems
- CI secret orchestration is outside the first product scope
- multi-app orchestration is outside the first product scope
