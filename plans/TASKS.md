## Decision Gates

| Gate | Passes when | On fail |
|---|---|---|
| Gate-A Path semantics | BOS-V2-001 through BOS-V2-004 are complete and all path/docs/git-policy checks agree | Pause all new domain work |
| Gate-B Foundation split | BOS-V2-006 through BOS-V2-010 are complete and legacy fixtures still migrate safely | Do not add metadata, screenshots, or device commands |
| Gate-C New domain entry | BOS-V2-012, BOS-V2-014, and BOS-V2-016 define bounded contracts before implementation | Keep domain commands out of public surface |
| Gate-D Release hardening | BOS-V2-018 proves resumable releases and explicit failure evidence | Keep release system at v1 hardening level |
| Gate-E Productization | BOS-V2-019 and BOS-V2-020 prove compatibility and fresh-clone behavior | Do not call the migration complete |

## Critical Path

`BOS-V2-001 -> BOS-V2-002 -> BOS-V2-003 -> BOS-V2-004 -> BOS-V2-006 -> BOS-V2-007 -> BOS-V2-008 -> BOS-V2-009 -> BOS-V2-010 -> BOS-V2-020`

## Notes

- The plan intentionally keeps metadata, screenshots, and device work off the critical path until the shared path, schema, adapter, and state contracts are safe.
- BOS-V2-003 is the most leverage-heavy task because it resolves the current contradiction between documented SSOT files and ignored runtime-only paths.
